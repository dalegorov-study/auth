# Бонусная задача. Свой мини-event loop

На лекции мы разбирали event loop на генераторах (пример
`lecture/3_asyncio/08_mini_asyncio.py`): задачи — это генераторы, они
«засыпают» через `yield from sleep(...)`, а планировщик по очереди
продвигает готовые задачи и будит спящие.

Чего там нет — способа **дождаться результата другой задачи**, как
`result = await task` в настоящем asyncio. Это и нужно добавить.

Целевой API:

```python
def fetch(name, delay):
    yield from sleep(delay)
    return f"data-{name}"


def main():
    tid_a = create_task(fetch("A", 0.2))
    tid_b = create_task(fetch("B", 0.1))
    result_b = yield from await_task(tid_b)  # ~0.1 с, B готов первым
    result_a = yield from await_task(tid_a)  # A уже готов - возвращается сразу
    print(result_a, result_b)


run(main())
```

Обе задачи выполняются одновременно, поэтому всё занимает ~0.2 с
(самая долгая), а не 0.3 с (сумма).

## Что сделать

В `mini_asyncio.py` уже есть рабочий планировщик со `sleep` и
`create_task`. Места, которые нужно дописать, помечены `TODO`:

1. **`AwaitTask`** — новый «системный вызов», dataclass с полем `tid`.
   Задача отдаёт его планировщику через `yield`, когда хочет дождаться
   задачу `tid`.
2. **`await_task(tid)`** — helper по аналогии с `sleep`: отдаёт
   `AwaitTask(tid)` и возвращает результат, который планировщик пришлёт
   обратно через `send`.
3. **Состояние планировщика**: где хранить результаты завершённых задач
   и кто ждёт какую задачу.
4. **`_handle_syscall`**: обработка `AwaitTask`. Если задача уже
   завершилась — сразу вернуть ждущему результат. Если нет — запомнить
   ждущего и **не ставить его в очередь**, пока задача не завершится.
5. **`_finish_task`**: сохранить результат и разбудить всех, кто ждал
   эту задачу, передав им результат.
6. **Обнаружение дедлока**: если готовых и спящих задач нет, а кто-то
   всё ещё ждёт — бросить `RuntimeError` со словом `deadlock`.

Ждать нужно без опроса в цикле («готово? нет? а сейчас?»): ждущая задача
просто не выполняется, пока её не разбудят.
