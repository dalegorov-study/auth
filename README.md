# auth
Семинарский сервис для модуля Backend-разработка

Локальное окружение (Python 3.12):

```sh
python3.12 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
```

Запуск сервиса на http://localhost:8003:

```sh
python main.py
```

Запуск тестов:

```sh
python -m pytest
```

Проверка API через Python и `requests`: запустите сервис в одном терминале,
а в другом выполните из корня репозитория:

```sh
.venv/bin/python check_api.py
```

Скрипт [check_api.py](check_api.py) выполняет 11 запросов, печатает HTTP-статусы
и JSON-ответы, проверяет ожидаемые результаты. Он создаёт пользователя
с уникальным именем, сохраняет cookie после входа и удаляет пользователя
в конце основного сценария. Статусы 404, 422 и 401 в последних трёх запросах ожидаемы.
При неожиданном результате скрипт завершается с ошибкой.
Адрес сервиса задаётся константой `BASE_URL` в начале `check_api.py`
(сейчас `http://localhost:8000`). Скрипт можно запускать из отладчика без аргументов;
перед запуском укажите порт, на котором работает сервис.

Ручная проверка API: откройте [requests.http](requests.http) в VS Code
с расширением [REST Client](https://github.com/Huachao/vscode-restclient)
и выполняйте запросы сверху вниз через `Send Request` при запущенном сервисе.
В файле есть регистрация, вход, чтение, деактивация и удаление пользователя,
а также примеры ошибочных запросов с ожидаемыми HTTP-статусами.
ID автоматически подставляется из ответа регистрации.

ID пользователей — целые числа, начиная с 1. После удаления ID не используется
повторно. Данные и счётчик хранятся в памяти и сбрасываются при перезапуске сервиса.
В JSON ID передаётся числом, в cookie `x-user-id` — строкой.
Для удаления и деактивации ID в URL должен совпадать с ID в cookie.
